# 日常工作流

按[快速开始](getting-started.md)初始化一次，随后正常向编码助手描述需求。它通过 `keelson guide` 按需读取指导。

**对话生命周期不等于工作生命周期。** 关闭窗口、继续提问或追加说明，都不会自动完成或重开变更。持久资料保存目标和证据，会话只是指向当前变更。

1. 读取项目意图、相关代码和受影响契约，不盘点整个仓库。
2. 复用已确定的决策，自行查证事实和处理可逆工程细节；只问真正属于用户的未决选择，每轮至多三个独立、前提已满足的问题。
3. 按工作规模创建 quick 或 spec 变更，先定义可观察的验收标准。
4. 实现及评审，计划文档保持适量。
5. 检查配置命令后首次使用 `keelson check --trust --record`；最终检查前完成验收项。
6. 所有门槛满足后，在已有授权内 `keelson land`，一起提交代码、契约和归档证据。

同一目标的补充留在原变更；独立目标创建新变更。恢复使用 `focus --auto`，有歧义时显式选定。只有人员或机器交接才需要 `handoff`。

检查失败就是失败，缺少运行环境要明确说明；模型的信心和手写 ledger 都不能代替证据。[信任与恢复](../verification.md)。
