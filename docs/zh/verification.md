# 验证与信任

最终编辑完成后，审阅配置中的 shell 命令，首次运行 `keelson check --trust --record`。命令变化会撤销本机信任；后续相同命令无需重复信任。

签名 `ledger.jsonl` 保存代码树、契约摘要、命令退出码、耗时及日志摘要；`evidence/<sha256>.log` 保存输出。`ledger.md` 仅供阅读，不授权归档。代码、规格、规则、配置、验收和决策变化后需要重新验证；局部检查、超时和输出超限都不能完成归档。

密钥、信任和会话位于 Git 私有目录，非 Git 项目使用用户缓存。初始化不修改 `.gitignore`。跨机器复制的证据须重新执行本机检查，历史签名仍保留。签名不隔离同权限进程，不证明模型身份或法律合规；有意义的测试和需求覆盖仍需审查。

归档拒绝正在运行的检查，通过备份和恢复日志处理写入失败。`land --force --reason` 必须明确原因并保留强制归档记录，不把失败检查改成成功。旧版 Markdown 证据不再满足门槛。

超时或输出超限后，CLI 尝试终止命令进程组，并限制自身等待输出管道关闭的时间。自行脱离进程组的后代仍可能存活；强制关闭管道时记录 `terminationUnconfirmed: true`，该次检查仍然失败。进程崩溃留下锁时，先确认对应写入进程已经退出，再只移除报错指明的那把锁；下一次归档会恢复未完成事务，并要求重新检查。

`attest` 导出的 JSON 不内嵌日志和所有历史公钥。需要让其他人完整核验时，应分享包含 `evidence/` 的整个 change 或 archive 目录。
