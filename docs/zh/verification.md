# 验证与信任

最终编辑完成后，审阅配置中的 shell 命令，首次运行 `keelson check --trust --record`。命令变化会撤销本机信任；后续相同命令无需重复信任。

签名 `ledger.jsonl` 保存代码树、契约摘要、命令退出码、耗时及日志摘要；`evidence/<sha256>.log` 保存输出。`ledger.md` 仅供阅读，不授权归档。代码、规格、规则、配置、验收和决策变化后需要重新验证；局部检查、超时和输出超限都不能完成归档。

工作树指纹使用 SHA-256，为路径、条目类型、执行位和内容摘要加上长度边界。每次快照重新读取内容，因此等长修改并恢复时间戳仍会使证据失效；不使用 Git status 或时间戳缓存。Git 提供文件集合及普通文件的未过滤内容摘要，含换行的路径直接读取。符号链接记录链接目标；嵌套 Git 仓库记录 HEAD，不包含其内部未提交的修改。非 UTF-8 路径明确报错。新格式会使旧 Git 与非 Git 指纹失效，升级后重新执行 `check --record`，历史签名仍可读取。

密钥、信任和会话位于 Git 私有目录，非 Git 项目使用用户缓存。初始化不修改 `.gitignore`。跨机器复制的证据须重新执行本机检查，历史签名仍保留。签名不隔离同权限进程，不证明模型身份或法律合规；有意义的测试和需求覆盖仍需审查。

归档拒绝正在运行的检查，通过备份和恢复日志处理写入失败。`land --force --reason` 必须明确原因并保留强制归档记录，不把失败检查改成成功。需要独立复核的变更，即使 `--force` 也不能绕过复核与新鲜完整检查。旧版 Markdown 证据不再满足门槛。

超时或输出超限后，CLI 尝试终止命令进程组，并限制自身等待输出管道关闭的时间。自行脱离进程组的后代仍可能存活；强制关闭管道时记录 `terminationUnconfirmed: true`，该次检查仍然失败。进程崩溃留下锁时，先确认对应写入进程已经退出，再只移除报错指明的那把锁；下一次归档会恢复未完成事务，并要求重新检查。

`attest` 导出的 JSON 不内嵌日志和所有历史公钥。需要让其他人完整核验时，应分享包含 `evidence/` 的整个 change 或 archive 目录。

新恢复日志保存相对路径，恢复前会检查全部目标和所需备份。Git 项目移动后可从随项目移动的私有运行目录恢复；旧日志中的绝对路径已失效、日志损坏或备份缺失时，CLI 会停止且不修改目标。保留日志和备份供人工恢复，不要通过删除它们绕过错误。

## 完成前的验收复核

spec 变更和所有包含 delta spec 的变更都需要当前的独立复核记录，quick 档也适用。没有 delta 的行为类 quick 变更在 frontmatter 写入 `review: independent`，或用 `new --review independent` 创建；纯文字、格式类 quick 修改保留轻量路径。

代理把原始请求和 `context --phase check` 交给全新上下文评审者。`keelson review --prepare [change]` 输出精确验收文字、合并后的完整规范和 `reportTemplate`。评审者逐项填写实际证据、区分性 `counterexamples`、各能力的契约检查、评审者身份及未解决的 `findings`。报告存入当前变更后执行 `keelson review --record .keelson/changes/<name>/<report>.json`。未解决问题阻止落地，由实现者修复后独立复核；缺少评审能力时如实报告。

报告绑定当前代码、请求、验收、上下文和契约。修改报告会使检查证据失效，因此先记录报告，再运行最终完整 `check --record`。签名绑定作为输入的报告，身份与观察质量仍由调用者提供，不能证明思考过程独立。升级后活动行为变更需要补复核；新增请求、上下文和复核绑定可能使旧检查记录过期。

MODIFIED/REMOVED 必须使用既有 Requirement 名称，ADDED 必须是新名称；误写会在修改规范前失败。不同标题仍可能表达冲突语义，因此评审者检查的是合并后的完整规范，代理应替换已废弃的要求与决定。
