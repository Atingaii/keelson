# 自动推进，状态明确

初始化一次，之后向编码 Agent 描述目标即可。下面的步骤由 Agent 管理，用户无需调用 Skill 或运行阶段命令。

1. **调查。** 读取仓库和已有决定。只讨论的请求保持只读；事实由 Agent 调查，不让用户猜。
2. **决策。** 简单缺口一次问一个；相互依赖的不确定性，一轮问完所有前提已确定的用户问题，每题给推荐与理由。答案解锁后续问题。已明确委托的选择在授权范围内解决，推荐本身不代表用户同意。
3. **启动。** 明确的小修改使用最小 quick 变更，较大契约变化使用 spec 变更。`start` 要求具体验收、已登记决策解决、前置变更完成，然后设为 `in-progress`、绑定会话并记录计划指纹。无关的未来问题应先移至独立变更或 roadmap。
4. **实现与复核。** 加载 `context --phase implement`。可版本化的 `context.json` 分别为实施和检查声明额外文件；当前规范、delta、需求、验收和适用规则不能因此被省略。实质修改交给新上下文中的独立审查者，提供 `check` 包和 diff，由实施者修复发现的问题，再复核受影响范围。宿主不支持独立上下文时，明确记录审查缺口。
5. **验证与保留。** 执行配置的检查，记录当前签名证据，对照实际行为核验验收。把可复用决定提升到 delta 规范或变更中的能力决策；`land` 合并到项目规范并归档证据，后续上下文包读取更新后的规范。

`request.md` 保留原始需求及重要补充，供复核使用；`decisions.json` 保存依赖树和答案依据；`execution.json` 记录已启动的计划。这些文件及共享规范可以入库，凭据、命令信任和会话指针留在本机。

## 哪些约束由什么执行？

| 机制 | 执行的约束与边界 |
| --- | --- |
| CLI 决策树 | 按已登记依赖排序，拒绝无效状态转换。`complete: true` 只描述已登记的树，Agent 仍需检查遗漏的重要分支。 |
| CLI 启动 | 未澄清计划不能启动；范围、决定或 delta 变化后启动记录失效。启动记录本身不证明用户已授权。 |
| Claude Code hooks | `PreToolUse` 在有效启动前拒绝受支持的文件修改工具，为 Agent/Task 注入阶段上下文。SessionStart 在压缩后恢复状态，UserPromptSubmit 重注入阶段指导；通用子代理启动保留父任务已给定的阶段。 |
| Codex hooks | 检查 `apply_patch` 的每个编辑路径和移动目标；SessionStart、UserPromptSubmit 恢复契约，SubagentStart 引导未关联的子代理自动绑定明确分配的任务并读取阶段上下文。需在宿主中信任项目和 hooks。 |
| CodeBuddy hooks | 文件门禁与 Task 提示注入使用其原生 `modifiedInput` 协议；SessionStart、UserPromptSubmit 恢复契约，Bash/PowerShell 桥接不透明会话标识且不授予权限。 |
| 其他宿主或未生效的 hooks | 安装入口指导 Agent 使用相同的启动和上下文命令，原生事件门禁需要受支持宿主中的 hooks 已启用且受信任。 |
| 验证与落地 | 正常落地要求当前完整签名检查及其他验收门禁通过。手写“通过”不是证据；显式 force 会记录为越过门禁。 |
| 独立审查与知识质量 | 上下文包支持分离，但需要宿主实际创建审查者、Agent 提炼有效知识。注入本身不能证明审查独立、发现穷尽或结果零缺陷。 |

Claude 门禁覆盖 `Edit`、`Write`、`MultiEdit` 和 `NotebookEdit`；CodeBuddy 还覆盖 `NotebookWrite`；Codex 检查 `apply_patch` 中的文件和移动目标。启动前允许维护 `.keelson/` 下的计划文件。任意 shell 命令和 MCP 写入不在此门禁范围内；它是流程机制，不是文件系统沙箱。宿主原有权限确认继续生效。协议与安装说明见[宿主支持](../platforms.md)。Codex 修改子代理参数需返回 allow，因此 Keelson 使用启动指导，由子代理自动读取上下文：已登记任务的派发提示必须带唯一且匹配的 `KEELSON_CHANGE=<name>` 行。子代理自动执行 `keelson focus` 和对应阶段的 `keelson context --phase`，并保留只读等范围限制；后续受支持事件按子代理自身 focus 注入上下文。Codex 子代理压缩或恢复时不会触发 SessionStart，因此子代理工具事件不按旧摘要去重；Agent 接续任务时也主动重读阶段上下文。

Codex 子代理的 CLI 与 hooks 使用自身线程身份。嵌套子代理根据明确分配的任务建立关联，不猜测根会话的 focus。切换或清空子代理的任务不会影响父会话或其他子代理。

仓库测试覆盖 CLI 转换、符合协议的 hook 事件输入、上下文恢复和安装升级，不等于真实 Agent 端到端效果证明。UI 工作仍需真实浏览器交互和视觉验收。

## 升级

安装最新版包后，在项目中执行 `keelson update`。未修改的 0.4.0/0.4.1 生成文件可被识别；后续安装记录内容摘要以支持安全更新。修改过的发现入口和 vendored 指导会被保留，并提示协调。指令文件中的受管区块会刷新，用户定制应放在区块外。已有项目事实和决策继续保留。
