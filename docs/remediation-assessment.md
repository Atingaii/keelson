# 整改初稿评估与实施口径

评估日期：2026-09-20。基线：`f6ce125`（0.3.0）。输入：用户提供的 `keelson-improvement-plan.md`，以其后文修订为参考，不把未经验证的叙述当作事实。

## 已核验

- 本机基线 88 项测试全部通过；初稿的历史 CI 失败统计不能推出当前测试失败。
- 完成门控只读取 `ledger.md`，手写成功记录确实可以绕过真实检查。
- 检查缺少超时；JSON 解析失败回退空对象；文件写入非原子；并发 ledger 更新是 read-modify-write。
- Markdown 标题解析不排除代码围栏；安装会复制可执行 hook 和整份方法论。
- 本仓库存在禁止来源归属的测试；移除该约束，公开对照项目与证据。

## 采纳与修正

1. 先完成数据安全、可核验的检查记录、双指纹、并发、规格无损读写和轻量安装；再做决策前沿与可复现评估。
2. `.keelson/` 是版本化项目资料，不添加任何 `.gitignore` 条目。本机密钥、信任记录、会话与缓存放 Git 私有目录；无 Git 时放用户缓存。
3. 指纹是标识而非秘密。使用完整摘要，不通过隐藏摘要宣称安全。结构化记录绑定代码、契约、实际命令、退出码和日志摘要；旧 Markdown 记录只作历史说明。
4. 本机签名只能发现误写与不持有本机密钥的篡改，无法阻止同权限程序或恶意仓库所有者重写事实。独立 CI 重跑才提供独立证据；不宣称 SLSA 认证或不可伪造。
5. 使用文件锁串行追加日志，不把 `PIPE_BUF` 的管道保证误用于普通文件。并发测试检查记录完整性和日志引用，不要求内容相同的日志强行产生不同哈希。
6. 保留现有 CLI 与 legacy spec 的兼容读取；不为未来功能提前分层重构。默认安装只放薄入口和项目数据，完整方法论按需从包读取。
7. “优秀”先定义为工程硬门控全通过、固定实际任务全部满足验收、零无证据完成声明、零破坏用户配置。时耗、token、澄清次数如实报告，不事后调阈值，不要求在不同定位工具的每一专属功能上胜出。

## 当前交付范围

实现安全内核、轻量 Codex 安装、决策记录、文档与宽幅品牌头图；在固定复杂开源仓库运行同模型的 Keelson / OpenSpec / Trellis / Superpowers 对照，保留全部运行结果、失败与修复轨迹。提交远程主分支并删除其余分支前先核验旧分支独有提交。

遥测、Discord、跨厂商模型、九个平台的实际宿主测试、企业合规认证、npm 发布和大规模采用度不属于本次证据能够支持的结论。未实测平台明确标注；不把未来路线图写成已完成能力。
